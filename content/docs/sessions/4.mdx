## 웹사이트에서 웹앱으로

### 한 장짜리 페이지의 한계

3회에 만든 `index.html`은 훌륭한 첫걸음이지만, 서비스가 되려면 부족한 점이 있습니다.

| 한 장 웹페이지 (3회) | 웹앱 (오늘부터) |
| --- | --- |
| 화면 하나 | 목록, 상세, 신청 완료 등 **여러 화면** |
| 모임이 늘면 글을 직접 고쳐야 함 | 모임 정보가 **데이터**로 따로 있어 화면이 알아서 그려짐 |
| 새로 고침하면 숫자가 사라짐 | 7회부터 데이터베이스에 **저장** |
| 내 컴퓨터에서만 | 6회부터 **인터넷 주소**로 공개 |

### 웹앱이란

<Term id="web-app">웹앱</Term>은 브라우저에서 돌아가지만 **앱처럼 동작하는** 웹사이트입니다. 로그인하고, 무언가를 신청하고, 내 정보가 저장됩니다. 예약 사이트, 은행 웹사이트, 온라인 쇼핑몰이 모두 웹앱입니다.

<Analogy title="전단지와 자판기">
  한 장 웹페이지는 <b>전단지</b>입니다. 보여 주기만 합니다. 웹앱은 <b>자판기</b>입니다. 버튼을 누르면 무언가 일어나고, 남은 수량이 줄어들고, 다 팔리면 "품절"이 뜹니다.
</Analogy>

### 프레임워크: 조립식 가구의 기본 틀

웹앱을 처음부터 다 만들려면 할 일이 너무 많습니다. 그래서 개발자들은 미리 만들어 둔 뼈대인 <Term id="framework">프레임워크</Term>를 씁니다.

<Analogy title="집을 지을 때">
  벽돌부터 굽는 사람은 없습니다. 검증된 자재와 공법을 씁니다. 프레임워크는 <b>검증된 자재와 공법의 묶음</b>입니다. 화면 이동, 데이터 불러오기, 빠르게 보여 주기 같은 기본 기능이 이미 들어 있습니다.
</Analogy>

이 과정에서는 <Term id="nextjs">Next.js</Term>를 씁니다.

| 왜 Next.js인가 | 설명 |
| --- | --- |
| 널리 쓰인다 | 많은 회사와 개인이 쓰는 대표적인 웹앱 프레임워크라서 자료가 많다 |
| AI가 잘 안다 | 많이 쓰이는 만큼 Claude도 잘 다룬다 |
| 공개가 쉽다 | 6회에 쓸 Vercel이 만든 프레임워크라 궁합이 좋다 |
| 앱으로 이어진다 | <Term id="react">React</Term> 기반이라, 12회의 Expo 앱과 만드는 방식이 닮았다 |

### 컴포넌트: 레고 블록

Next.js(React)는 화면을 작은 부품으로 나눠 만듭니다. 이 부품을 <Term id="component">컴포넌트</Term>라고 합니다.

```
모임 목록 화면
├─ 머리말 (모임 이름, 로고)
├─ 모임 카드  ← 같은 부품을 여러 번 씀
├─ 모임 카드
├─ 모임 카드
└─ 꼬리말
```

- "모임 카드"를 한 번 만들어 두면, 모임이 10개든 100개든 같은 부품으로 그립니다.
- 카드 모양을 바꾸고 싶으면 **부품 하나만** 고치면 모든 카드가 바뀝니다.
- 그래서 고쳐 달라고 할 때 "모임 카드에서…"처럼 부품 이름으로 말하면 정확합니다.

<Analogy title="도장 찍기">
  카드 100장에 같은 무늬를 그리려면 도장을 하나 파서 찍는 것이 빠릅니다. 컴포넌트는 <b>화면용 도장</b>입니다. 도장을 고치면 앞으로 찍는 모든 카드가 바뀝니다.
</Analogy>

### 개발 서버와 localhost

웹앱을 만드는 동안 Claude Code는 내 컴퓨터에서 **개발 서버**를 켭니다. 그러면 브라우저에서 `http://localhost:3000` 같은 주소로 웹앱을 볼 수 있습니다.

| 말 | 뜻 |
| --- | --- |
| 개발 서버 | 만드는 동안 내 컴퓨터에서 웹앱을 돌려 주는 프로그램 |
| <Term id="localhost">localhost</Term> | "바로 이 컴퓨터"라는 뜻의 주소. **나만** 열 수 있다 |
| 3000 | 같은 컴퓨터 안의 여러 프로그램을 구분하는 번호(포트) |

<Analogy title="집에서 시험 삼아 차려 보는 식당">
  가게를 열기 전에 집 부엌에서 메뉴를 만들어 가족에게 먼저 먹여 보는 것과 같습니다. localhost는 <b>우리 집 부엌</b>입니다. 손님(다른 사람)은 아직 못 옵니다. 가게 문을 여는 것(공개)은 6회입니다.
</Analogy>

- 개발 서버가 켜져 있는 동안 코드를 고치면 **브라우저가 알아서 바뀝니다.**
- 컴퓨터를 끄거나 Claude 앱을 닫으면 개발 서버도 꺼집니다. 다음에는 "다시 켜줘"라고 하면 됩니다.

## CLAUDE.md: 프로젝트 규칙 메모

### 매번 같은 말을 반복하지 않으려면

"한국어로 답해줘", "쉽게 설명해줘", "큰 변경 전에는 계획부터"… 이런 말을 매번 하기는 번거롭습니다. 프로젝트 폴더에 <Term id="claude-md">CLAUDE.md</Term> 파일을 두면, Claude Code가 **대화를 시작할 때마다 먼저 읽습니다.**

<Analogy title="새 직원에게 주는 업무 안내서">
  새 직원이 오면 "우리 가게 규칙" 한 장을 줍니다. 손님에게 인사는 이렇게, 마감은 이렇게. CLAUDE.md는 <b>Claude Code를 위한 우리 프로젝트 안내서</b>입니다.
</Analogy>

```markdown
# 우리 모임 웹앱 규칙
- 답변과 화면 글자는 한국어로
- 나는 코딩을 처음 배우는 사람이니 쉽게 설명하기
- 큰 변경 전에는 계획부터 보여주기
- 기능 하나를 마치면 무엇을 바꿨는지 3줄로 알려주기
```

- 짧을수록 좋습니다. 규칙이 너무 많으면 중요한 것이 묻힙니다.
- 쓰다가 "이건 매번 말하네" 싶은 것이 생기면 하나씩 더합니다.

## 요즘 업계에서는

### AI 시대에 더 많이 쓰이는 언어

GitHub가 해마다 내는 보고서 Octoverse 2025에 따르면, 2025년 8월 **TypeScript가 처음으로 GitHub에서 가장 많이 쓰이는 언어**가 됐습니다. GitHub는 그 이유 중 하나로 AI를 꼽았습니다 ([Octoverse 2025](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)). TypeScript는 JavaScript에 "이 칸에는 날짜만 들어간다" 같은 규칙을 더한 언어로, AI가 만든 코드의 실수를 미리 잡아 줍니다. 오늘 만드는 Next.js 웹앱도 대부분 TypeScript로 만들어집니다.

### 프로젝트 규칙 파일이 표준이 되다

CLAUDE.md처럼 **AI가 먼저 읽는 프로젝트 안내서**는 이제 여러 AI 코딩 도구가 함께 쓰는 방식이 됐습니다. 도구마다 파일 이름은 조금씩 다르지만 생각은 같습니다. 사람에게 일을 맡길 때처럼, AI에게도 우리 프로젝트의 규칙을 글로 알려 주는 것입니다.

### 목업에서 웹앱까지가 짧아졌다

예전에는 목업을 받은 개발자가 화면을 처음부터 다시 만들었습니다. 지금은 목업 캡처와 기획서를 AI에게 함께 주면 **그 자리에서 동작하는 첫 버전**이 나옵니다. 그래서 요즘 팀들은 "완벽한 기획서"보다 "빨리 만들어 보고 고치기"를 더 자주 택합니다.

## 시연

강사가 2회에 만든 목업 캡처와 `기획서.md`를 빈 폴더에 넣고, Claude Code에게 계획을 받습니다. 계획을 승인하면 Next.js 프로젝트가 만들어지고, 가짜 모임 6개가 든 목록 화면이 `localhost:3000`에 뜹니다. "모임 카드에 남은 자리를 크게" 같은 수정을 말로 하고, 브라우저가 바로 바뀌는 것을 보여 줍니다. 마지막으로 브라우저의 휴대폰 화면 미리 보기로 점검합니다.
