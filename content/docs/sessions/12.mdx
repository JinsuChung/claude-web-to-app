## 오늘의 흐름

| 시간 | 내용 | 하는 일 |
| --- | --- | --- |
| 0–10분 | 지난 시간 돌아보기 | 홈 화면에 설치한 PWA, 과제에서 나온 불편한 점 나누기 |
| 10–35분 | 앱은 어떻게 만들어질까 | 네이티브 앱, React Native, Expo, Expo Go |
| 35–50분 | 요즘 업계에서는 | "목업 → Expo" 흐름, 크로스 플랫폼이 표준이 된 이유 |

오늘은 이 과정에서 가장 신기한 순간 중 하나를 경험합니다. **내가 말로 만든 앱이 내 휴대폰 안에서 움직이는 순간**입니다. 아직 스토어에 올리지는 않지만, 진짜 네이티브 앱을 내 손에서 눌러 봅니다.

## 앱은 어떻게 만들어질까

### 원래는 두 번 만들어야 했습니다

휴대폰은 크게 두 종류입니다. 안드로이드와 아이폰(iOS)입니다. 둘은 서로 다른 언어를 씁니다.

| 휴대폰 | 원래 쓰는 언어 | 만드는 도구 |
| --- | --- | --- |
| 안드로이드 | Kotlin, Java | Android Studio |
| 아이폰 | Swift | Xcode (Mac에서만) |

그래서 예전에는 같은 앱을 **두 번, 두 팀이** 만들었습니다. 작은 모임이나 가게가 앱을 만들기 어려웠던 가장 큰 이유입니다.

### React Native: 한 번 만들어 두 휴대폰에

<Term id="react-native">React Native</Term>는 이 문제를 풀기 위해 나왔습니다. 4회에 배운 React 방식(화면을 작은 부품, 즉 <Term id="component">컴포넌트</Term>로 나눠 만드는 방식)으로 한 번 만들면, 안드로이드와 아이폰에서 각각 진짜 네이티브 화면으로 바뀌어 돌아갑니다. 이런 방식을 <Term id="cross-platform">크로스 플랫폼</Term>이라고 합니다.

<Analogy title="동시통역사">
  React Native는 동시통역사와 같습니다. 우리는 한 가지 말(React)로 이야기하고, 통역사가 안드로이드에게는 안드로이드 말로, 아이폰에게는 아이폰 말로 전해 줍니다. 그래서 버튼 하나를 만들면 안드로이드에서는 안드로이드다운 버튼, 아이폰에서는 아이폰다운 버튼이 됩니다.
</Analogy>

### Expo: React Native를 쉽게 쓰게 해 주는 도구 상자

React Native만으로도 앱을 만들 수 있지만, 설치하고 설정할 것이 많습니다. <Term id="expo">Expo</Term>는 그 준비를 대신해 주는 **도구 상자**입니다.

| Expo가 해 주는 일 | 쉽게 말하면 |
| --- | --- |
| 프로젝트 만들기 | 명령 한 줄로 앱의 뼈대가 생깁니다 |
| 화면 이동(Expo Router) | 파일을 하나 만들면 화면이 하나 생깁니다. 4회의 Next.js와 같은 방식입니다 |
| 휴대폰 기능 | 카메라, 알림, 위치 등을 쓰는 부품이 준비돼 있습니다 |
| 미리 보기(Expo Go) | 만드는 중인 앱을 내 휴대폰에서 바로 봅니다 |
| 빌드와 출시(EAS) | 설치 파일 만들기, 스토어 제출을 클라우드에서 합니다 (14회) |

React Native 공식 문서도 새 앱을 시작할 때 Expo 같은 프레임워크를 쓰라고 권합니다. 시작 명령은 <Fact k="expo.start" />입니다.

<Analogy title="밀키트">
  React Native가 좋은 재료라면, Expo는 손질된 재료와 양념, 조리 순서까지 들어 있는 밀키트입니다. 처음 요리하는 사람도 실패 없이 한 끼를 만들 수 있습니다. 나중에 실력이 늘면 재료를 직접 골라 쓸 수도 있습니다.
</Analogy>

### Expo Go: 만드는 중인 앱을 휴대폰에서 미리 보기

<Term id="expo-go">Expo Go</Term>는 휴대폰에 설치하는 앱입니다. 노트북에서 만드는 중인 앱을 **설치 파일 없이** 휴대폰에서 바로 보여 줍니다.

1. 노트북에서 Claude Code가 개발 서버를 켜면 화면에 **QR 코드**가 나옵니다.
2. 휴대폰으로 그 QR 코드를 찍으면 Expo Go 안에서 내 앱이 열립니다.
3. 노트북에서 코드를 고치면 휴대폰 화면도 **몇 초 만에 바뀝니다.**

<Analogy title="리모컨이 아니라 거울">
  Expo Go는 노트북에 있는 앱을 휴대폰에 비춰 주는 거울입니다. 그래서 노트북이 꺼지거나 개발 서버가 멈추면 휴대폰에서도 앱이 열리지 않습니다. 노트북 없이도 열리는 진짜 설치 파일은 14회에 만듭니다.
</Analogy>

<DeepDive title="Expo Go는 연습용입니다">

Expo 공식 문서는 Expo Go를 **"배우는 사람이 Expo를 빠르게 써 보기 위한 놀이터"**라고 소개합니다 ([Expo Go 안내](https://docs.expo.dev/get-started/expo-go/)). 실제 출시할 앱은 "개발 빌드(development build)"라는 나만의 앱으로 만듭니다. 이 과정에서는 다음처럼 나눠 씁니다.

- **12–13회:** Expo Go로 빠르게 만들고 확인합니다.
- **14회:** EAS로 진짜 설치 파일을 만들어 봅니다.

또 하나, Expo Go는 **최신 Expo 버전(SDK)에 맞춰** 업데이트됩니다. Claude Code가 만든 프로젝트와 휴대폰의 Expo Go 버전이 맞지 않으면 "호환되지 않는다"는 메시지가 나옵니다. 그럴 때는 그 메시지를 그대로 Claude Code에 붙여 넣으면 됩니다.

아이폰용 Expo Go는 2026년 9월부터 **노트북(Expo CLI)과 Expo Go 앱 모두 같은 Expo 계정으로 로그인**해야 개발 중인 앱을 열 수 있습니다 ([Expo 변경 안내, 2026-09-03](https://expo.dev/changelog/expo-go-57-login)). 아이폰 사용자는 실습 전에 Expo Go 앱에서 로그인해 두세요. 안드로이드도 로그인해 두면 실행 중인 앱이 자동으로 목록에 떠서 편합니다.

</DeepDive>

### 웹앱과 앱, 무엇이 같고 무엇이 다른가

| 구분 | 우리 모임 웹앱 (4–10회) | 우리 모임 앱 (12–14회) |
| --- | --- | --- |
| 뼈대 | Next.js | Expo |
| 공통점 | React, 컴포넌트, 파일 하나가 화면 하나 | 같음 |
| 화면 이동 | 링크와 주소 | 아래쪽 탭, 화면 쌓기(뒤로 가기) |
| 미리 보기 | 브라우저의 localhost | 휴대폰의 Expo Go |
| 공개 | Vercel 배포 | EAS 빌드 → 스토어 |
| 데이터 | Supabase | **같은 Supabase** (13회) |

웹앱을 만들어 본 경험이 그대로 이어집니다. 그리고 2회에 만든 **기획서와 목업이 다시 설계도가 됩니다.**

## 요즘 업계에서는

### "목업 → Expo" 흐름

요즘 앱을 빠르게 만드는 사람들은 이렇게 일합니다.

1. **Claude 채팅**으로 아이디어를 기획서로 정리하고, 아티팩트로 클릭되는 목업을 만듭니다 (2회).
2. 목업 캡처와 기획서를 **Claude Code**에 주고 Expo 앱으로 옮기게 합니다 (오늘).
3. **Expo Go**로 휴대폰에서 눌러 보며 말로 고칩니다.
4. 데이터베이스(Supabase)를 붙이고 (13회), **EAS**로 빌드해 출시합니다 (14회).

예전에는 디자이너가 그린 시안을 개발자가 몇 주에 걸쳐 앱으로 옮겼습니다. 지금은 그 사이를 AI 에이전트가 채웁니다. 사람이 할 일은 **"이 화면이 맞나, 이 버튼이 제대로 동작하나"를 확인하는 것**입니다. 1회에 이야기한 에이전틱 엔지니어링의 모습 그대로입니다.

### 크로스 플랫폼이 표준이 된 이유

- React Native 공식 문서는 새 앱을 시작할 때 Expo 같은 프레임워크 사용을 권합니다 ([React Native 시작하기](https://reactnative.dev/docs/environment-setup)).
- 웹(React)과 앱(React Native)이 같은 방식을 쓰니, **한 사람이 웹과 앱을 다 만드는 일**이 흔해졌습니다. AI 도구도 이 조합을 특히 잘 다룹니다. 학습 자료와 예시가 많은 기술일수록 AI가 정확하게 만들기 때문입니다.
- 아이폰 앱은 원래 Mac에서만 만들 수 있었지만, Expo의 클라우드 빌드(EAS Build)는 Expo의 클라우드에 있는 Mac에서 빌드합니다 ([EAS Build 안내](https://docs.expo.dev/build/introduction/)). 그래서 **Windows 노트북으로도 아이폰 앱을 빌드할 수 있습니다.**

<Callout title="Windows 사용자도 걱정하지 마세요">
  오늘 실습은 Windows와 macOS 모두 똑같이 할 수 있습니다. 휴대폰도 안드로이드와 아이폰 모두 Expo Go로 확인합니다. 노트북에 Android Studio나 Xcode를 설치할 필요가 없습니다.
</Callout>

## 시연

강사가 2회에 만든 우리 모임 목업 캡처와 `기획서.md`를 Claude Code에 주고 Expo 앱을 만들게 합니다. 계획(플랜 모드)을 먼저 받아 탭 구성을 확인한 뒤 진행합니다. 개발 서버의 QR 코드를 휴대폰으로 찍어 앱을 열고, "참석 신청 버튼을 초록색으로 크게"라고 말로 고쳐 휴대폰 화면이 몇 초 만에 바뀌는 것을 보여 줍니다. 일부러 와이파이를 바꿔 연결이 끊기게 한 뒤 터널 방식으로 다시 연결하는 장면도 포함합니다.
