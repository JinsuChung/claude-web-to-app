## 수업 전 준비 체크리스트

- [ ] 수강생 노트북 환경 확인: Windows/macOS 비율, 설치 권한, 강의실 와이파이(같은 와이파이에서 휴대폰 연결이 막히는지)
- [ ] Claude 유료 플랜 안내: 1–2회는 무료로도 가능, 3회부터 Claude Code 필요
- [ ] 노트북 1대로 전 회 리허설. 특히 4회 Node.js, 7–8회 Supabase, 12회 Expo Go 연결, 14회 EAS 빌드 대기 시간
- [ ] 자료실의 `our-moim-starter.zip`이 Windows 기본 압축 풀기에서 한글 깨짐 없이 풀리는지 확인
- [ ] 회별 사전 준비 공지: 5회 전 GitHub, 6회 전 Vercel, 7회 전 Supabase, 10회 전 Claude Console, 12회 전 Expo Go
- [ ] 시연용 백업 녹화: 네트워크 문제로 라이브 시연이 안 될 때 대비
- [ ] 10회 실습용 API 키: 키마다 낮은 월 사용 한도, 수업 후 폐기 일정
- [ ] 각 회 페이지의 &ldquo;요즘 업계에서는&rdquo; 숫자와 링크를 수업 직전에 한 번 열어 최신인지 확인 (순위·요금은 자주 바뀜)

## 2시간 수업의 기본 리듬

| 시간 | 내용 |
| --- | --- |
| 0–10분 | 지난 회 돌아보기, 과제 2–3명 공유 |
| 10–40분 | 개념 설명 (비유 중심), 시뮬레이터 |
| 40–50분 | 요즘 업계에서는 (트렌드, 사례) |
| 50–60분 | 시연 |
| 60–70분 | 쉬는 시간 |
| 70–110분 | 실습 (발표 모드 <Kbd keys="T" /> 타이머) |
| 110–120분 | 정리, 퀴즈, 과제 안내, 다음 회 준비물 |

각 회 페이지의 &ldquo;오늘의 흐름&rdquo; 표가 그 회에 맞춘 시간표입니다. 실습이 밀리면 &ldquo;선택&rdquo;·&ldquo;심화&rdquo; 실습은 과제로 넘기세요.

## 우리 반 진행 현황 (별명 참여)

- 1회 실습 시작 전에 홈 화면의 **별명으로 참여하기**를 다 같이 눌러 참여시키기 (1분). 참여 후 체크하면 홈 현황판에 실시간으로 모임
- 수업 중 홈의 현황판을 띄워 &ldquo;지금 몇 명이 이번 회 실습을 끝냈는지&rdquo; 보여 주면 참여를 끌어올리기 좋음. 순위는 보여 주지 않고, 완료 소식만 띄움
- 기록 위치: Vercel → Storage → Blob → `class/production/participants/` (참가자 1명 = 파일 1개, 파일명은 별명 해시)
- 테스트·장난 기록 지우기: 본인이 사이드바에서 &ldquo;내 기록 지우기&rdquo;, 또는 강사가 위 폴더에서 해당 파일 삭제
- 다음 기수 시작 전 초기화: 위 폴더의 파일을 모두 삭제 (로컬 개발은 `class/dev/`, 미리보기 배포는 `class/preview/`로 분리)

## 발표 모드

회 페이지에서 <Kbd keys="P" /> → 소제목 단위 슬라이드. <Kbd keys="T" /> 실습 타이머, <Kbd keys="Q" /> 현재 페이지 QR(수강생이 같은 위치를 열 수 있음), <Kbd keys="esc" /> 종료.

## 회별 진행 요점

| 회 | 꼭 짚을 것 | 자주 막히는 곳 |
| --- | --- | --- |
| 1 | 답을 주는 AI와 일을 끝내는 AI의 차이. 바이브 코딩 → 에이전틱 엔지니어링. 검증이 실력 | 결제·로그인. 회원가입은 수강생 본인이 직접 |
| 2 | 좋은 요청의 다섯 요소. 목업은 버리는 것이 정상. 기획서는 이후 모든 회의 설계도 | 기능을 너무 많이 넣음 → MVP 3–5개로 줄이기 |
| 3 | 폴더 = 프로젝트. 계획 먼저 보기, 권한 창은 읽고 누르기, 되돌리기 | 폴더를 잘못 열기(바탕화면 전체 등) |
| 4 | 목업 → Next.js. CLAUDE.md로 규칙 고정. 보이는 대로 말해서 고치기 | Node.js 설치 후 앱 재시작 안 함, 포트 충돌 |
| 5 | 커밋 = 세이브 포인트. .gitignore와 비밀 키 | GitHub 로그인 연동(브라우저 인증 창) |
| 6 | 푸시하면 자동 배포. 공개 주소는 누구나 본다. Hobby는 비상업 | 빌드 에러 → 로그를 그대로 붙여 넣기 |
| 7 | DB = 같이 쓰는 똑똑한 엑셀. SQL은 읽을 수만 있으면 됨 | 환경변수 미설정, 테이블 이름 오타 |
| 8 | 인증 vs 권한. RLS는 꼭 켠다. 공개 키와 비밀 키 | RLS 켜고 정책 없음 → 아무것도 안 보임 |
| 9 | 테이블 사이 관계. 테스트 체크리스트로 확인하는 습관 | 정원 처리, 사진 용량 |
| 10 | 만드는 AI vs 일하는 AI. 키는 서버에만. 사람이 확인하는 설계, 프롬프트 인젝션 | 키를 브라우저 코드에 넣는 실수, 크레딧 미충전 |
| 11 | 모든 서비스가 스토어 앱일 필요는 없다. PWA 먼저 | 아이폰은 사파리 공유 버튼 → 홈 화면에 추가 |
| 12 | Expo가 업계 표준인 이유. 목업 → Expo | 같은 와이파이 아님 → 터널 모드 |
| 13 | 데이터베이스 하나, 화면 둘. 앱에는 공개 키만 | 로그인 유지(세션 저장), 환경변수 이름(EXPO_PUBLIC_) |
| 14 | 출시는 준비물. 개인정보처리방침은 사람이 검토 | 빌드 대기 시간(무료는 줄 서기), 등록비 |
| 15 | 운영과 피드백. 3분 데모. 다음 30일 계획 | 발표 시간 관리 (타이머 3분) |

## 예상 질문

- **&ldquo;챗GPT랑 뭐가 다르냐&rdquo;**: 답을 주는 것과 일을 끝내는 것의 차이. 1회 시뮬레이터로 보여 주기. 다른 도구가 나쁘다가 아니라 용도가 다르다로 전달
- **&ldquo;이러면 개발자는 필요 없냐&rdquo;**: 업계는 오히려 &ldquo;만드는 사람의 천장이 높아졌다&rdquo;고 봅니다. 큰 서비스·보안·운영은 여전히 전문가의 일. 이 과정은 &ldquo;내 문제를 내가 푸는&rdquo; 수준까지
- **&ldquo;내 정보가 AI로 나가는 것 아니냐&rdquo;**: 대화 내용은 AI 서비스로 전송된다는 사실을 솔직하게. 실습은 가상 데이터, 민감 정보는 넣지 않기
- **&ldquo;돈이 계속 드냐&rdquo;**: Claude 구독 외에는 이 과정 규모에서 무료 요금제로 충분. 스토어 등록비는 선택
